**One call of mine (BUG-122).** The bug as filed says "update changes Bonsai's own guard line". It does so on
purpose: the first pack that brings roles switches Bonsai's guard to also judge agent calls, which is stricter. Letting
`--yes` write that changed line alone would let an agent change Bonsai's own guard line, which this repo's rules keep
for you. So the fix is the half that loosens nothing: `init` takes several packs, so a two-pack project is linked in
one step, and an update that adds a pack with roles keeps asking for your `--allow-exec`, with a message that says why.

**Not changed.** Shell reads and writes stay outside the guard (BUG-048's limit); no release or tag; the workflow
repo's commit stays local for your push.

about 2 h; C (Sonnet; the workflow pack) about 30 min. A fresh Opus verifier (tests and correctness, and security for
the guard) on A and B. CI on each branch.
