## For the director (plain words)

**What this will do.** Four pieces, as you chose on 22 Oct:
1. **The README rebuilt.** One line on what you get, then the short demo, a "What you get" table (each part, what it
   does for you, one command), the "How it works" picture, install in three lines (each system's steps folded away),
   "A first project" with the dry run's eleven fixes, "What it is not" in a few sentences, and the rest (packs,
   platforms, the old 0.4.3, where the design lives) short, with links. About 8-10 KB, against 6.2 KB today, most of it
   the steps.
2. **The "How it works" picture**, drawn as an image with a light and a dark version that GitHub switches by itself:
   an agent's edit or command, the guard (allowed, or refused with its next step), the log, the ladder (red holds the
   session, green is done).
3. **A short scripted recording** (about 30-45 seconds, a GIF at the top of the README) of Bonsai's own commands in a
   fresh project: link it, `check` and `status`, a climb refused with its next step, then green. Made from a script kept
   beside it, so it is rebuilt in seconds when the words change.
4. **A real Claude Code session, recorded** (about 1-2 minutes, sped up where nothing happens; the caption says so):
   a small project with a task running; Claude is asked for a change; it tries to edit `bonsai.yaml` and the guard
   refuses with the next step; it says it is done while the tests are red and the stop gate holds it; it fixes the
   work and climbs green; `bonsai logs` shows each step. Claude's moves are its own, not scripted; an agent records a
   few takes and keeps the clearest. Your YouTube recording with a voice-over comes later, as your own piece.

Everything goes in `docs/demos/`, each recording next to the script it was made from. You see the picture, both
recordings and the README before anything lands.

**One fact that changes the README.** The stop gate (Claude held until the proof is green) works only in a session
started with the task named: `BONSAI_TASK=T-0001 claude`. Today's README never says so, so a new person would never see
it. The recording starts Claude that way, and step 6 of "A first project" gains one line saying it.

**Which Bonsai the recordings show.** A test build of today's `main`, made in the scratch folder (the way every trial
here runs), not the installed rc.1: an agent may not run the person's `bonsai update --yes` with the installed copy,
and the test build may, inside its scratch folder only. It prints what `main` prints. rc.2's fixes change a few of
Bonsai's words (for example what `update` says first). So the final recordings are made last, from a build of `main`
after rc.2's fixes land and before you tag rc.2, so they show what 1.0 prints. The scripted one costs seconds to redo;
the session is re-recorded only if what it shows has changed. Every frame of both is checked for a home-folder path,
a user name or an account detail before it is kept.

**How we know it works.** An agent follows the new README's "A first project" from nothing, exactly as written, the
way the rc.1 dry run did. It must reach a green climb with no step the README fails to explain. A fresh Opus verifier
checks every claim in the README against the code.

**Choices that are yours.** None beyond approving. My calls, for you to overrule: the README's words are written by an
Opus builder (it is the product's front page); the picture by a Fable agent (visual design); no PNG files (this repo
ignores them outside the old 0.4.3 demo folder, so the picture is SVG and the recordings GIF); the old 0.4.3 demo in
`assets/demos/` stays where it is (the README does not point at it today, and will not).

**Risk.** Low: no code, no protected file. The real-session recording is the uncertain part: Claude may not take the
same path every time, so several takes may be needed. If a clean take does not come within about three hours of
trying, the work stops and I bring you the best take and the options.

**Size.** About 9-13 hours of agent time: the README 2-3, the picture 1-2, the scripted recording 1, the session
recording 3-5, the dry run and the verifier 2. Most of it runs side by side. Your steps: approve this plan; during the
dry run, one `bonsai update --yes` in your own terminal (step 6 of the README, as in the rc.1 dry run; I send the exact
line); look at the picture, the recordings and the README before they land.
