# Plan: one system for time, before 1.0

Two readers. **The director** reads the first part only (down to Size) and reads no code: it is in plain words. The
**builder and verifier** read the rest. Evidence: the auditor's inventory `~/bonsai-checks/T-5795/inventory.md`
(`M-2026-10-21-0bf20cef`), the research `~/bonsai-checks/T-5795/research.md` (`M-2026-10-21-f491fe5d`), the run report
`records/runs/R-2026-10-21-T-5795-time-handling.md`. Revision 2, after the facts review `M-2026-10-21-979a667b` (FAIL,
seven blocking findings B1-B7, each answered below); round 2 `M-2026-10-21-b5a38f91` PASS, its six notes folded in.

## For the director (plain words)

**What this will do.** Bonsai becomes the only clock, as you chose on 21 Oct ("Full: script + stamps + now"; "option
1"). Six pieces:
1. **One written rule for time**, in the formats. Machine records (the log, questions and answers, messages, climb
   results) stay as they are: UTC with its `Z`. Every new time inside a file you open (run reports, the sessions
   table) is written like git: your local time with its offset, `2026-10-21 12:49 +05:30`. A day (a task's dates, a
   run report's id) is the writer's local day. Old records are left exactly as they are, and still read.
2. **`bonsai now`**, your time script: prints the time in that form, and the UTC and day forms on request. Every
   agent instruction that needs a time says "run `bonsai now`".
3. **Local time everywhere Bonsai prints** (`status`, `logs`, `agents`, `asks`, `messages`, the session's opening
   lines): your zone, offset shown; `--utc` gives the stored form; the machine-readable `--json` output keeps UTC.
4. **The sessions table's new rows in local time with their offset.** Old rows stay as written (the table only ever
   grows); Bonsai reads both.
5. **"Now" told to agents**: on each of your prompts, by a hook, and at the start of each subagent. This changes one
   of Bonsai's own hook lines, so it needs your `bonsai update --allow-exec --yes` once, which I will ask for with the
   exact line.
6. **Fresh stamps checked when they are written.** When an agent fills an empty date or time (or writes a new file) in a
   task, run report, memory note, or a plan's approval date, or changes STATE's or a memory note's "updated" day, Bonsai's guard checks it against its own clock: a time must carry
   its offset and be within 10 minutes of now; a day must not be in the future or more than 2 days back. Otherwise
   the edit is refused, and the refusal says "run `bonsai now`". Correcting a date that is already there is allowed
   (a true past date can be recorded), and so is adding the offset to an old time. Run reports stop carrying a
   hand-typed table of run times: the hours come from the log (the sessions table's per-task rows), and the report
   names the agents' message ids.

**What it does not catch.** A time written by a shell command (`sed`, `cat >`), by git, or by you in your own editor
is not checked by the guard; `bonsai check` then flags a new time without an offset. A wrong date typed as a
"correction" of an existing one passes. Other pack documents' dates (a playtest's, a brief's) are not checked, since
no format says which of their fields is a date.

**Choices that are yours.** One. You picked "Bonsai writes task dates itself when a task moves". Bonsai's own rule is
that it never moves a task (`CLAUDE.md`, "Is not"): moves are an agent's edit or a studio's command, so there is no
moment where Bonsai writes the date by itself. The plan therefore does piece 6: the agent writes the date, taken from
`bonsai now`, and the guard refuses a fresh stamp that is not Bonsai's clock's. **The other way** is a new `bonsai task
move` command that moves and stamps, which changes that rule. I recommend piece 6.

**Risk.** It touches the formats you confirmed on 7 Oct (a new formats set, 11, by addition only: old records stay
valid; checked over all 152 run report times and 874 sessions table times on disk, none fails), the guard, and a hook
line. The guard check looks only at the date and time fields named above, so ordinary edits pass. The "now" hook must
never block a prompt: if `bonsai` cannot run, the prompt goes through with no time line. The work stops and asks you if
any piece would need to remove or rename a format field.

**Size.** About 12-18 hours of agent time across six builders, at most two side by side, in four batches, then a
fresh Opus verifier (guards and hooks are on its list). Your steps: approve this plan; one `bonsai update --allow-exec
--yes` after piece 5 lands. It lands before rc.2, so 1.0 carries it.

### Approach

0. **The contract (orchestrator, after approval).** `design/contract.md` gains a section "Time": instants in machine
   records RFC 3339 UTC with `Z`, milliseconds where the record already has them, seconds where it has seconds (both
   listed; precision unchanged); **document times** `YYYY-MM-DD HH:MM ±HH:MM` (run `started`/`finished`, new sessions
   rows); a document time with no offset is legacy: in a run report it means "offset unknown", in the sessions table
   it means UTC (as `sessions.schema.json:102,110` already says); **days** `YYYY-MM-DD`, the writer's local day (task
   `created`/`started`/`finished`, STATE `updated`, memory `updated`, pack dates, a run id's day); machine-record days
   (log `w-` files, ask day files, message ids) stay UTC days, so said. The sessions table stays append-only
   (`design/contract.md:662`): old rows are never rewritten.
1. **Piece A, formats set 11 (Opus builder).** `run.schema.json` `started`/`finished` and `sessions.schema.json` row
   `start`/`end` accept `^[0-9]{4}-[0-9]{2}-[0-9]{2} [0-9]{2}:[0-9]{2}( [+-][0-9]{2}:[0-9]{2})?$` (a strict superset of
   today's pattern); every time field's description names its form and zone (the inventory's part 1). The two
   unpatterned status fields (`status.schema.json` ~:987, ~:1394) stay unpatterned (no narrowing). New
   `now.schema.json` (`bonsai.now/1`: `local`, `utc`, `day`, `offset`, `zone`), its example, `contract.md`'s output
   list (in step 0). Trick files: a run time with an offset, one without (legacy), one with `IST` (refused).
   `formats/manifest.json` set 11; `formats/README.md`. Set 11 is this task's; T-5793 (after 1.0) takes the next.
2. **Piece B, `internal/timefmt` and `bonsai now` (Sonnet builder).** One package owns every form: `Doc(t, loc)`,
   `Day(t, loc)`, `UTC(t)`, `Show(t, loc, utc bool)`, and parsers for each including the legacy forms and a zone-less
   sessions row read as UTC. The zone comes from `time.Local` in production; **every function takes a
   `*time.Location`, and tests pass one from `time.LoadLocation` with `time/tzdata` embedded in the test binary only**
   (Go on Windows ignores `TZ`: `zoneinfo_windows.go` `initLocal`), covering Asia/Kolkata, UTC and a DST zone, on both
   sides. A numeric offset always, never an abbreviation. `bonsai now [--utc|--day] [--json]` (the `bonsai.now/1`
   output), help text, the reference page.
3. **Piece C, printed output (Sonnet builder).** Every printed time in the inventory's part 3 goes through
   `timefmt.Show`; each command takes `--utc`; `--json` unchanged. `bonsai logs --day` takes a local day, reads the
   UTC-day files that span it and keeps only the records whose instants fall in that local day; its refusal text
   (`cmd/bonsai/logs.go:80`) and `logs.schema.json`'s file `day` description (UTC, ~:138) say which day is which. `bonsai message --show` keeps printing the file as stored, and its trust line adds the
   `created` time in local form. The SessionStart opening lines show the last climb's time in local form.
4. **Piece D, the sessions table (Sonnet builder).** New rows in `timefmt.Doc`; old rows untouched. `sessions.Key`,
   `clean/rows.go:54`, `Missing` and the sort compare by **instant** (a zone-less row read as UTC), never by the text,
   so an old row is never re-added in the new form and the order stays by time. The header names the form. A test
   with a real mixed table (old rows, then new) proves no duplicate and the order.
5. **Piece E, now on each prompt and each subagent start (Opus builder; hook lines).** A synchronous `bonsai hook now`
   on UserPromptSubmit printing `Now: 2026-10-21 12:49 +05:30 (local)`; on SubagentStart the same through JSON
   `hookSpecificOutput.additionalContext` (the docs give no plain-stdout path there). A scripted session (a runner,
   `claude-here`, scratch) proves each reaches the model before the piece is called done. It must never block: exit 0
   always, no blocking JSON, a short timeout; `bonsai` missing means no line and the prompt runs. Its cost is measured
   on both sides and reported (a second process start per prompt); the guard's own call (~8 ms WSL, ~49 ms Windows) is the
   comparison, and more than twice it on either side is the stop point (Risk, below). Written by `internal/engine/settings.go`; no hook line calls `bash` by name. A long
   `-p` run with no new prompt gets no refresh: the docs say "run `bonsai now`".
6. **Piece F, fresh stamps checked (Opus builder; guard).** A new check in the guard's document path, placed **before**
   the `status_writes` gate in `tripwire()` (`internal/guard/tripwire.go:178` returns early in agents mode, which
   is this repo's), so it runs in both modes. It judges an Edit or Write of: task (`created`, `started`, `finished`),
   run (`started`, `finished`), state (`updated`), memory (`updated`; `documentOf`, `tripwire.go:83-110`, gains
   memory), and pack kinds' fields named in their `stamp` (plan, feature, spec `approved`; decision `date`; options
   `decided`). Rules: a fresh stamp (a listed field going from empty or `null` to a value, every listed field of a new file a Write
   creates, and any change to STATE's or memory's `updated`, which are never empty and mean "the day it was rewritten")
   must parse in the set-11 form;
   a time must carry its offset and lie within 10 minutes of the guard's clock; a day must not be after today nor
   more than 2 days before it. Any other listed field that already had a value may change freely (a correction), and adding an
   offset to a legacy time whose digits stay the same passes (B3). Refusal rule `time-not-now`, `next: run: bonsai
   now` (or `bonsai now --day`). `bonsai check`: a document time with no offset, **in a field the uncommitted change
   wrote**, is a finding; legacy values already committed are not. Docs: `base:task`, `base:run`, `base:state`,
   `base:memory` say the form and "take it from `bonsai now`"; `base:run` says the hours are the sessions table's
   per-task rows and drops any hand-typed run-time table. The workflow pack's templates get the same lines in its next
   version (its tag is the director's), after 1.0 unless they ask.
7. **Records (the orchestrator).** `CLAUDE.md`'s run report rule becomes: name each run's message id and model; the
   hours are `.bonsai/sessions.md`'s per-task rows. Past run reports stay as they are.

### Risk in the code

- **The guard check refusing ordinary work:** it judges only the listed fields, only when they go from empty to a
  value. Stop and report if a kind's date field cannot be found from its schema or `stamp`.
- **Midnight and DST:** the day window covers midnight; tests in a DST zone. A wrong machine clock makes every stamp
  wrong but consistent; out of scope.
- **SubagentStart:** if a scripted session shows its `additionalContext` does not reach the subagent, piece E covers
  prompts only and the docs say subagents run `bonsai now`. Stop and report rather than invent another channel.
- **Hook cost:** if the "now" line costs more than twice the guard's own call on either side, stop and report the
  numbers.
- **Format change by removal:** none planned. If any piece finds it needs one, it stops: that comes to the director
  first (their (B)).

## Amendment 1 (21 Oct, the director): the offset as its own field

Piece A's audit (`M-2026-10-21-22870bde`) found that widening the run and sessions patterns breaks `design/contract.md`
§2.2 ("within a major, changes only add"; `formats/compare_test.go` fails any pattern change), and that old readers,
the installed rc.1 among them, would refuse the new form. Asked, the director chose **"A separate offset field"**. So,
over steps 0, 1, 4 and 6 above:
- **Run reports** keep `started`/`finished` as `YYYY-MM-DD HH:MM` (pattern unchanged), in the writer's local time, and
  gain an optional field `offset` (`^[+-][0-9]{2}:[0-9]{2}$`, e.g. `+05:30`), the offset both times are in. A report
  with no `offset` is legacy ("offset unknown").
- **The sessions table**: rows gain an optional `offset` (a column); a row with it is in local time at that offset, a
  row without it is UTC (every old row). Readers compare rows by instant.
- **No pattern changes**; `compare_test.go` stays as it is. Set 11 adds: run `offset`, the sessions row `offset`,
  `now.schema.json`, descriptions naming every time field's zone, and the trick files (a run with `offset`, one
  without, one with `offset: IST`, refused).
- **The guard (piece F):** a fresh `started` or `finished` needs `offset` present in the file after the edit, and the
  time read at that offset within 10 minutes of now.
- **Registry:** piece A owns the `now` row in `internal/format/format.go`, `internal/format/now.go`, the regenerated
  `docs/reference/lists.md` and `internal/reader/set_test.go`'s case count, so A's tip climbs green; piece B rebases
  on A and uses them.
- The contract's section 23 is amended to match in the records commit after batch 1 lands.

## Amendment 2 (21 Oct, the director): record in UTC only, convert on display

Asked how the sessions table should take local time (rc.1 refuses a tenth column), the director amended the rule
itself: **"anyplace we record time, i want it to be in utc only. whenever we need to display, we can always convert it
to whatever timezone we need to. by always recording in utc we ensure that we have a consistent timestamp
everywhere"**. This replaces "option 1" and Amendment 1. Over the steps above:
- **Every recorded time is UTC.** Machine records as today (`...Z`). Run reports' `started`/`finished` keep their form
  `YYYY-MM-DD HH:MM` and pattern, and from set 11 mean UTC. Every day field (a task's dates, STATE's and memory's
  `updated`, the packs' dates, a run id's day) is the UTC day. The sessions table is already UTC: unchanged.
- **Legacy:** a run report or task written before set 11 recorded local time, offset unknown; never rewritten. The
  contract names the cutover (set 11's release); `check` judges only new writes.
- **No `offset` field** (Amendment 1's is dropped before landing: nothing leaves a released format). **Piece D is
  cut**: no sessions table change. Set 11 adds `now.schema.json`, the descriptions naming every time field as UTC,
  and trick files.
- **`bonsai now`** prints the record form in UTC, `2026-10-21 08:19`; `--day` the UTC day; `--iso` the instant form
  `2026-10-21T08:19:04.325Z`; `--local` the display form `2026-10-21 13:49 +05:30` for a person; `--json` all of them
  (`bonsai.now/1`: `utc`, `day`, `iso`, `local`, `offset`, `zone`).
- **Go's two local-day writers** (`internal/engine/state.go:55`, `internal/workspace/personal.go:83`) and the run
  reports' retention cutoff (`internal/engine/checkdocs.go:696`) move to UTC (piece B).
- **Display (piece C)** unchanged: local with the offset, `--utc` for the stored form.
- **The guard (piece F):** a fresh stamp is checked against the UTC clock (a time within 10 minutes, a day not after
  the UTC today nor more than 2 days before it).
- **Now told (piece E):** `Now: 2026-10-21 08:19 UTC (local 13:49 +05:30)`; agents record the UTC form.
